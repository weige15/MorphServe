# Candidate artifact smoke analysis

## Confirmatory results

The pre-registered prediction was supported:

- The unmodified editable install failed with `error: package directory 'morphserve' does not exist`.
- `import MorphServe` from the exact source tree reached `MorphServe/__init__.py` and failed because it imports nonexistent `swiftllm`.
- `import morphserve` and `import swiftllm` both failed because neither package exists in the release layout.
- `EngineConfig.add_cli_args` generated `model_path`, but the dataclass requires `org_model_path`; construction failed with an unexpected `model_path`. Ten additional morphing fields were not generated by the parser.
- The C++ extension compiled successfully against Python 3.12.3, PyTorch 2.4.0+cu121, host CUDA toolkit 12.4, and GCC. This supports source-level build viability.
- A direct extension import failed with `libc10.so` not found. The pre-registered changed-hypothesis follow-up ran `import torch; import swiftllm_c` and succeeded. It exposed all 13 expected bindings, so the built extension is importable when PyTorch preloads its shared libraries. The initial direct failure is retained as a loader-order fact, not binary incompatibility.
- Vendor manifests passed before and after. The test operated on a disposable exact copy and did not modify the vendored artifact.
