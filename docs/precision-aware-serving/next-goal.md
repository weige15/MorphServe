# Next pi-goal: projection-level precision signal before a new scheduler

Source baseline: `weige15/MorphServe@c370077a6ecf2ef83a266e9a240f11764d9984c7`.

This is the next executable research step only. It intentionally does **not** build a precision-aware continuous-batching scheduler yet.

## Architecture decision for this step

- Keep `weige15/MorphServe/main` frozen as the MorphServe reproduction/evidence line.
- Treat the current branch only as bootstrap/staging. New paper work should live in a clean sibling repository once created, with the exact source commits recorded.
- Reuse the **modified SwiftLLM substrate from `weige15/MorphServe@c370077...`** for later serving/runtime experiments. Do not restart from pristine `interestingLSY/swiftLLM`, because upstream intentionally omits quantization while the current substrate already has the validated AWQ-Marlin, segmented-KV, runtime-transition, telemetry, benchmark, and test machinery needed later.
- For the present numerical falsification step, do not force the experiment through SwiftLLM if a smaller controlled harness is more reliable. `weige15/qaq_baseline@a5f4d5d52358c7b9740ecec448db5279c6af5ddc` may be used for nested W4/W6/W8 sensitivity measurements, but its reconstructed-FP16 path is **numerical evidence, not low-bit serving-speed evidence**.
- Do not naively mix original FP16 projections with AutoAWQ packed projections inside a layer. The MorphServe fork explicitly loads AutoAWQ-rescaled norms together with the selected packed linears, so per-projection AWQ hybrids require a correctness audit before they can be treated as evidence.

## Run this goal first

```text
/goal --tokens 80000 Produce the strongest evidence-backed characterization of whether query-dependent precision sensitivity has stable and exploitable structure below the transformer-layer level, especially across Q/K/V/O projections, using weige15/MorphServe@c370077a6ecf2ef83a266e9a240f11764d9984c7 as the read-only systems/reference baseline, weige15/qaq_baseline@a5f4d5d52358c7b9740ecec448db5279c6af5ddc and its frozen negative whole-query endpoint-routing result as prior evidence, the QAQ and MorphServe paper material already available to the project, the existing modified SwiftLLM/AWQ-Marlin code when implementation inspection is needed, and the available local model/GPU/test environment. Attempt to determine, rather than assume, whether precision sensitivity varies materially by query, layer, attention-versus-MLP block, and Q/K/V/O projection; whether Q/K/V asymmetry is repeatable on held-out inputs; and what is the finest structured precision unit that is scientifically meaningful before arbitrary per-element irregularity. Start with the smallest mathematically controlled static ablation harness and do not build a router, continuous-batching scheduler, custom heterogeneous kernel, asynchronous loader, or joint workload controller under this goal.

Before collecting claim-bearing measurements, audit the quantization representation and norm/rescaling dependencies. In particular, verify whether original FP16 weights and AutoAWQ-packed Q/K/V/O matrices can be combined within one layer without violating the calibrated representation. If that exact hybrid is not mathematically valid, do not approximate silently: use the nearest controlled representation that can independently vary projection precision, such as the already-validated nested W4/W6/W8 reconstruction path, clearly label it as sensitivity-only evidence, and leave hardware-valid packed mixed execution for the next stage. Implement only the instrumentation required to select precision at explicit projection/block boundaries and to record the actual applied profile.

Attempt a hierarchy of static comparisons that includes uniform high precision, uniform low precision, layer-wise mixed precision, attention-versus-MLP mixed precision, and feasible Q/K/V/O-specific profiles. Use multiple query/task classes and both calibration and held-out inputs; include representative prefill-like and decode-like tensor shapes where the harness permits it, but do not turn shape microbenchmarks into serving claims. For every query/profile retain the relevant output-quality or logit/loss delta, the selected precision profile, model/checkpoint and tokenizer revision, seed, command, code commit, and enough raw output to independently recompute the primary statistics. Measure whether the identity/ranking of sensitive projections changes across queries, not merely whether average quantization error differs among Q, K, V, and O. Quantify within-query profile separation, between-query variation, rank stability, and held-out repeatability. Treat the frozen qaq_baseline result—0/3 tasks passing the actual fixed6 gate for whole-query fixed4/fixed8 endpoint routing—as a boundary condition: a positive fine-grained result must demonstrate information that the failed whole-query endpoint choice did not capture rather than relabeling that result.

Verify mathematical correctness of every mixed path with targeted tests and constant-profile equivalence controls; verify that any cached/autoregressive test does not accidentally change token prefixes when claiming an isolated precision effect; run the relevant existing regression tests; repeat enough GPU/model measurements to estimate run-to-run noise; and use an analysis path plus a separate audit/recomputation path for the decision metrics. Use a non-decision pilot only to establish feasibility, numerical noise, runtime, and defensible practical thresholds. Freeze the held-out prompt/query IDs, candidate profiles, primary metrics, exclusion rules, and GO/NO-GO criteria before inspecting the final held-out comparison. A GO must require both a repeatable held-out query-by-projection interaction that exceeds the frozen noise/practical gate and a structured profile space small/regular enough to plausibly execute as grouped/tiled GPU work; average Q/K/V sensitivity differences alone are insufficient. A NO-GO is a valid result if query-specific projection structure is too small, unstable, or only obtainable at hardware-hostile granularity.

Verify the final outputs include: (1) a tested, reproducible projection/block precision-ablation harness; (2) frozen protocol/configuration for the held-out comparison; (3) raw or losslessly summarized per-query/per-profile evidence with manifests and regeneration commands; (4) a table/analysis separating layer, attention/MLP, and Q/K/V/O effects and quantifying query-by-projection interaction plus uncertainty; (5) an explicit audit of the AutoAWQ norm/rescaling coupling and which mixed representations are valid versus invalid; and (6) a GO/NO-GO decision on whether it is justified to spend the next phase building precision-aware continuous batching. End with a report that separates CONFIRMED FINDINGS, SUPPORTED BUT UNCERTAIN FINDINGS, BLOCKED QUESTIONS, and REMAINING UNCERTAINTY. If the required model/GPU, mathematically valid representation, or minimum held-out evidence is unavailable, stop as blocked with the exact evidence collected, attempted paths, blocker, and next input needed instead of weakening the claim or building a scheduler anyway. Between iterations, choose the smallest experiment that can falsify the strongest remaining assumption, then re-audit scope and evidence before continuing.
```

## Gate to the following stage

Only after this goal returns **GO** should the next pi-goal implement heterogeneous precision inside continuous batching. The first runtime mechanism should be the simplest measurable one—precision-compatible grouping/microbatching—before considering shared-low-bit plus high-bit refinement or custom heterogeneous kernels.
